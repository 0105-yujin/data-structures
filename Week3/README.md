# Week3: 연결 리스트와 ADT

## 1. 실습 목표
- ADT(무엇을 제공하는가)와 구현(어떻게 구현하는가)을 구분
- 배열 기반 리스트와 연결 리스트의 접근·삽입·삭제 비용 비교
- `Node`, `LinkedList`로 단순 연결 리스트의 핵심 연산 구현
- 링크 재연결로 리스트 뒤집기, 두 포인터로 중간 노드 찾기

## 2. 구현한 연산
| 연산 | 설명 | 시간 복잡도 |
|---|---|---|
| `insert_first` | 맨 앞 삽입 | O(1) |
| `insert_after` | 주어진 노드 뒤에 삽입 | O(1) |
| `insert_last` | 맨 뒤 삽입 (tail 없음) | O(n) |
| `delete_first` | 첫 노드 삭제 | O(1) |
| `delete_after` | 주어진 노드 다음 노드 삭제 | O(1) |
| `search` | 값으로 인덱스 탐색 | O(n) |
| `get_node` / `get` | i번째 노드 접근 | O(n) |
| `reverse` | 링크만 재연결해 뒤집기 | O(n) |
| `middle` | slow/fast 포인터로 중간 값 | O(n) |

## 3. 코드 설명
- **insert_after**: 새 노드의 link를 먼저 `prev.link`에 연결한 뒤 `prev.link`를 새 노드로 바꿔야 기존 연결을 잃지 않습니다.
- **insert_last**: 빈 리스트면 `insert_first`를 호출하고, 아니면 마지막 노드까지 순회한 뒤 붙입니다.
- **delete_first / delete_after**: 비어 있거나 다음 노드가 없으면 `IndexError`를 발생시키고, 크기(`size`)를 함께 갱신합니다.
- **reverse**: `prev`, `curr`, `next_node` 세 변수로 새 노드 없이 link 방향만 반대로 돌린 뒤 `head`를 `prev`로 바꿉니다.
- **middle**: slow는 한 칸, fast는 두 칸씩 이동하고 fast가 끝에 닿으면 slow가 중간입니다.

## 4. 테스트 결과
- 기본 상태, 삽입, 중간 삽입, 삭제·탐색·접근 테스트 모두 통과
- 도전 과제: `[10, 20, 30, 40, 50]`의 `middle()`은 30, `reverse()` 후 `[50, 40, 30, 20, 10]`

## 5. 생각해 보기 요약
- **tail을 저장하면**: 맨 뒤 삽입이 O(1)로 빨라지지만, 단방향 리스트에서 마지막 노드를 삭제할 때는 직전 노드를 찾으려고 처음부터 순회해야 합니다.
- **인덱스 접근이 잦으면**: 배열이 적합합니다. 주소 계산으로 O(1) 접근이 가능하기 때문입니다.
- **연결 리스트가 항상 빠르지 않은 이유**: 배열은 메모리가 연속이라 캐시 지역성이 좋고, 연결 리스트는 노드가 흩어져 있어 캐시 미스가 잦기 때문입니다.

## 6. 느낀 점
배열과 달리 연결 리스트는 포인터만 바꿔서 삽입, 삭제를 한다는 점을 확인할 수 있었습니다. slow/fast 포인터로 한 번의 순회에 중간 값을 찾는 방법이 신기했습니다.
